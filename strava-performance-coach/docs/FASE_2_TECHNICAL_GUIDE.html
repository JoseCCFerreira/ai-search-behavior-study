Código Principal: strava_oauth.py

class StravaOAuth:
    """Gerencia fluxo OAuth 2.0 com Strava"""
    
    AUTHORIZE_URL = "https://www.strava.com/oauth/authorize"
    TOKEN_URL = "https://www.strava.com/oauth/token"
    SCOPES = "read,activity:read_all,profile:read_all"
    
    def __init__(self):
        self.client_id = settings.strava_client_id
        self.client_secret = settings.strava_client_secret
        self.redirect_uri = settings.strava_redirect_uri
    
    def generate_authorization_url(self) -> str:
        """Cria URL para utilizador fazer login"""
        state = secrets.token_urlsafe(32)
        params = {
            "client_id": self.client_id,
            "response_type": "code",
            "redirect_uri": self.redirect_uri,
            "scope": self.SCOPES,
            "state": state
        }
        return f"{self.AUTHORIZE_URL}?{urlencode(params)}"
    
    def exchange_code_for_tokens(self, code: str) -> TokenData:
        """Troca código por tokens (POST a Strava)"""
        response = requests.post(
            self.TOKEN_URL,
            data={
                "client_id": self.client_id,
                "client_secret": self.client_secret,
                "code": code,
                "grant_type": "authorization_code",
            }
        )
        data = response.json()
        token_data = TokenData(...)
        self.save_tokens(token_data)
        return token_data

🗄️ DuckDB: Banco de Dados Analítico Local

O que é DuckDB?

DuckDB é um banco de dados SQL embarcado, otimizado para análise de dados (OLAP) em vez de transações (OLTP). Perfeito para este projeto porque:

  • Sem servidor: Nenhuma instalação necessária
  • Local: Tudo fica no seu computador
  • Rápido: Otimizado para queries analíticas
  • SQL: Usa SQL padrão
  • Ficheiro único: `.duckdb` é um ficheiro
  • Python-friendly: Integrado com pandas

Arquitetura DuckDB vs PostgreSQL

Aspecto DuckDB PostgreSQL
Setup Nenhum Servidor
Arquivo .duckdb (ficheiro) Diretório completo
Otimizado para OLAP (análise) OLTP (transações)
Performance Muito rápido em analytics Bom para todas
Parallelismo Multi-core automático Manual
Ideal para Análise local Aplicações web

Como Funciona

import duckdb

# Conexão (cria ficheiro se não existir)
conn = duckdb.connect('database/strava_coach.duckdb')

# Criar tabela
conn.execute("""
    CREATE TABLE IF NOT EXISTS activities (
        id INTEGER PRIMARY KEY,
        name VARCHAR,
        distance FLOAT,
        moving_time INTEGER,
        average_speed FLOAT,
        imported_at TIMESTAMP
    )
""")

# Inserir dados
conn.execute("""
    INSERT INTO activities VALUES
    (1, 'Morning Run', 10.5, 2400, 4.375, NOW())
""")

# Query
result = conn.execute("""
    SELECT name, distance, average_speed
    FROM activities
    WHERE distance > 5
    ORDER BY average_speed DESC
""").fetchall()

print(result)
# [(Morning Run, 10.5, 4.375)]

🏅 Arquitetura Medalha: Bronze, Silver, Gold

Conceito

A Arquitetura Medalha é um padrão de design para organizar dados em camadas de qualidade progressiva. Cada camada tem um propósito específico:

🥉 Bronze Layer - Raw Data

Objetivo: Armazenar dados brutos, exatamente como vêm do Strava

  • Tabelas:
    • raw_strava_events - Eventos webhook recebidos
    • raw_strava_activities - JSON bruto das atividades
  • Características:
    • Sem transformação
    • Sem limpeza
    • Duplicados permitidos
    • Nunca deletado (auditoria)
  • Exemplo: 
    raw_strava_activities {
  raw_activity_id,
  source_activity_id,
  raw_payload: JSON,
  imported_at
}

🥈 Silver Layer - Cleaned & Normalized

Objetivo: Dados limpos, normalizados e validados

  • Tabelas:
    • stg_activities - Atividades normalizadas
    • stg_events - Eventos processados
  • Transformações:
    • Conversão de unidades (m → km, s → min)
    • Tratamento de nulos
    • Validação de dados
    • Deduplicação por source_id
    • Type casting correto
  • Exemplo: 
    stg_activities {
  activity_id,
  activity_date,
  distance_km,        -- convertido
  moving_time_minutes, -- convertido
  average_speed_kmh,   -- calculado
  created_at,
  updated_at
}

🏆 Gold Layer - Business Insights

Objetivo: Dados prontos para análise e dashboards

  • Tabelas:
    • fct_activity_metrics - Métricas calculadas
    • daily_summary - Agregado diário
    • weekly_summary - Agregado semanal
    • coach_recommendations - Recomendações
  • Transformações:
    • Métricas calculadas (performance_score, training_load)
    • Agregações (daily, weekly, monthly)
    • Ratios e índices (pace/HR)
    • Previsões simples
  • Exemplo: 
    fct_activity_metrics {
  activity_id,
  performance_score,    -- 0-100
  training_load,        -- calculado
  intensity_score,      -- calculado
  fatigue_impact,       -- calculado
  efficiency_score      -- calculado
}

Fluxo de Dados

Strava API/Webhook
       ↓
   Bronze Layer (raw)
       ↓
   Transformação (cleanup, validation)
       ↓
   Silver Layer (cleaned)
       ↓

🔧 dbt: Data Build Tool

O que é dbt?

dbt (data build tool) é uma ferramenta que transforma dados em seu data warehouse. Para o Performance Coach, usaremos dbt para:

  • Transformar dados de Bronze → Silver → Gold
  • Calcular métricas
  • Agregar dados
  • Testar qualidade de dados
  • Documentar transformações

Arquitetura dbt

Raw Data (Strava)
       ↓
  dbt models/ (transformações SQL)
       ├── staging/ (Silver)
       ├── marts/ (Gold)
       └── intermediate/ (helper tables)
       ↓
  Transformações executadas
       ↓
  Nova tabelas em DuckDB
       ↓
  Tests executados
       ↓
  Documentação gerada
       ↓
  Pronto para Streamlit/ML

Exemplo de dbt Model (Silver)

-- models/staging/stg_activities.sql

{{ config(
    materialized='table'
) }}

SELECT
    raw_activity_id,
    activity_id,
    athlete_id,
    activity_name,
    activity_type,
    activity_date::DATE as activity_date,
    
    -- Unit conversions
    distance_meters / 1000.0 as distance_km,
    moving_time_seconds / 60 as moving_time_minutes,
    elapsed_time_seconds / 60 as elapsed_time_minutes,
    (distance_meters / 1000.0) / (moving_time_seconds / 3600.0) as average_speed_kmh,
    
    -- Pace calculation
    CASE 
        WHEN distance_km > 0 
        THEN moving_time_minutes / distance_km 
        ELSE NULL 
    END as average_pace_min_km,
    
    average_heartrate,
    max_heartrate,
    total_elevation_gain,
    created_at,
    updated_at

FROM {{ source('raw', 'raw_strava_activities') }}
WHERE raw_payload IS NOT NULL

Exemplo de dbt Model (Gold)

-- models/marts/fct_activity_metrics.sql

{{ config(
    materialized='table'
) }}

SELECT
    activity_id,
    
    -- Performance Score (0-100)
    CASE
        WHEN average_speed_kmh >= 7 THEN 85
        WHEN average_speed_kmh >= 6 THEN 75
        WHEN average_speed_kmh >= 5 THEN 65
        ELSE 55
    END as performance_score,
    
    -- Training Load
    (moving_time_minutes * average_heartrate / 100.0) as training_load,
    
    -- Intensity
    CASE
        WHEN average_heartrate / max_heartrate > 0.90 THEN 'high'
        WHEN average_heartrate / max_heartrate > 0.75 THEN 'moderate'
        ELSE 'low'
    END as intensity_level,
    
    created_at

FROM {{ ref('stg_activities') }}
WHERE activity_date >= CURRENT_DATE - INTERVAL 90 DAY

📊 Streamlit: Dashboard Interativo

O que é Streamlit?

Streamlit é um framework Python para criar dashboards e aplicações de dados interativas rapidamente, sem HTML/CSS/JS.

Vantagens para Performance Coach

  • ✓ Pure Python (sem web development skills)
  • ✓ Hot reload (vê mudanças em tempo real)
  • ✓ Componentes prontos (charts, tables, filters)
  • ✓ Integrado com pandas, plotly, numpy
  • ✓ Deploy fácil (Streamlit Cloud)
  • ✓ Perfeito para MVP

Exemplo Simples

import streamlit as st
import pandas as pd
import plotly.express as px
import duckdb

st.set_page_config(page_title="Strava Coach", layout="wide")

st.title("🏃 Strava Performance Coach")

# Sidebar
with st.sidebar:
    date_range = st.date_input("Select date range")
    activity_type = st.multiselect("Activity Type", ["Run", "Ride", "Walk"])

# Query data
conn = duckdb.connect('database/strava_coach.duckdb')
df = conn.execute("""
    SELECT * FROM stg_activities
    WHERE activity_date BETWEEN ? AND ?
""", [date_range[0], date_range[1]]).df()

# Display metrics
col1, col2, col3, col4 = st.columns(4)
col1.metric("Total Activities", len(df))
col2.metric("Total Distance", f"{df['distance_km'].sum():.1f} km")
col3.metric("Avg Pace", f"{df['average_pace_min_km'].mean():.2f} min/km")
col4.metric("Avg HR", f"{df['average_heartrate'].mean():.0f} bpm")

# Chart
st.subheader("Performance Over Time")
chart_data = df.groupby('activity_date').agg({
    'average_speed_kmh': 'mean',
    'average_heartrate': 'mean'
})

st.line_chart(chart_data)

# Table
st.subheader("Recent Activities")
st.dataframe(df.sort_values('activity_date', ascending=False))

Exemplo: Clustering de Atividades

from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler
import pandas as pd

# Dados
df = pd.read_sql("""
    SELECT distance_km, moving_time_minutes, average_heartrate
    FROM stg_activities
""", conn)

# Normalizar
scaler = StandardScaler()
X_scaled = scaler.fit_transform(df)

# Clustering
kmeans = KMeans(n_clusters=3, random_state=42)
df['cluster'] = kmeans.fit_predict(X_scaled)

# Interpretar
clusters = df.groupby('cluster').agg({
    'distance_km': 'mean',
    'moving_time_minutes': 'mean',
    'average_heartrate': 'mean'
})

print(clusters)
# Cluster 0: Easy (short, low HR)
# Cluster 1: Medium (medium pace, medium HR)
# Cluster 2: Hard (long/fast, high HR)

Exemplo: Previsão de Performance

from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import train_test_split

# Features e target
X = df[['distance_km', 'total_elevation_gain', 'moving_time_minutes']]
y = df['performance_score']

# Split
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)

# Modelo
model = RandomForestRegressor(n_estimators=10, random_state=42)
model.fit(X_train, y_train)

# Avaliar
score = model.score(X_test, y_test)  # R² score
print(f"Model R² Score: {score:.2f}")

# Feature importance
importances = pd.DataFrame({
    'feature': X.columns,
    'importance': model.feature_importances_
}).sort_values('importance', ascending=False)

print(importances)
